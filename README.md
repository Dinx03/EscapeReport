| เฟส | ทำอะไร | สถานะ |
|---|---|---|

หลักการที่ใช้ตลอดทั้งสองเฟส

1. **ประเมินตามจริง ไม่ชม** — จุดที่ coupling สูงหรือยังไม่ modular จริง ต้องเขียนตรง ๆ
   เพราะอาจารย์จะตรวจ
2. **ทุกประโยคต้องมีหลักฐาน** — ชี้ `ไฟล์:บรรทัด` หรือค่าใน scene/prefab จริง
   ห้ามเดาจากชื่อไฟล์ ห้ามใช้ความรู้ทั่วไปของ Unity แทนข้อมูลโปรเจกต์
3. **ไม่มีข้อมูล = ถาม ไม่ใช่แต่ง** — แรงจูงใจ ผลทดสอบ ปัญหาระหว่างพัฒนา มีแต่ผู้เขียนที่รู้
4. ใช้ศัพท์เทคนิคภาษาอังกฤษได้เมื่อไม่มีคำไทยที่ใช้กันจริง ส่วนที่มีทับศัพท์ไทยให้ใช้ไทย

## กฎที่ใช้กับพื้นที่นี้

1. การสำรวจโปรเจกต์เกมเป็น **read-only อย่างเคร่งครัด** — ห้ามแก้ script/scene/prefab/
   Inspector/Project Settings, ห้ามสร้างหรือลบ asset, ห้ามเข้า Play Mode, ห้ามรัน test,
   ห้าม `refresh_unity` และห้ามเขียนไฟล์ใด ๆ ลงใน `EscapeRoom/`
2. ทุกข้อความใน `md/` ต้องมีหลักฐานกำกับ: ชี้ไฟล์และบรรทัด
   (เช่น `Assets/Scripts/Clock/ClockMovement.cs:136`) หรือระบุว่าเป็นข้อมูลจากผู้เขียน
   (ทำเครื่องหมาย `[จากผู้เขียน]`)
3. จุดที่ยังไม่มีคำตอบทำเครื่องหมาย `[ต้องถาม]` ไว้ ห้ามเติมเอง
4. **อ้างจากไฟล์วิจัย ไม่ใช่จาก `CLAUDE.md`** — เอกสารในโปรเจกต์มี 4 จุดที่นับไม่ตรงกับไฟล์จริง
   (47 นาฬิกา → จริง 46, 28 implementation → จริง 29, ตาราง asmdef ของ `Puzzle`,
   และเส้น `Player → Clock` ที่หายไป)
